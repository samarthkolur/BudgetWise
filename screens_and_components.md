# BudgetWise — Screens, Routes & Components

Inventory of the Flutter app's routing, screens, modal sheets, and reusable
components, as of 2026-09-30. Generated by reading `app/lib/` directly
(`core/router/`, `core/widgets/`, and every `features/*/presentation/`
folder) — not from BUILD.md or CLAUDE.md, so treat this as a snapshot of the
code, not of the plan.

---

## Routes

Defined in [`app/lib/core/router/routes.dart`](app/lib/core/router/routes.dart)
and wired in [`app/lib/core/router/app_router.dart`](app/lib/core/router/app_router.dart).

| Path | Screen | Nav type |
| --- | --- | --- |
| `/sign-in` | `SignInScreen` | pushed, standalone (outside the shell) |
| `/onboarding` | `OnboardingScreen` | redirect target when no budget exists for the current month |
| `/insights` | `InsightsScreen` | pushed from Home (health-score row / "View all") |
| `/settings` | `SettingsScreen` | pushed from Home (avatar) |
| `/dashboard` | `DashboardScreen` | tab, inside `ShellRoute` / `AppShell` — **initial location** |
| `/ledger` | `LedgerScreen` | tab |
| `/goals` | `GoalsScreen` | tab |
| `/alerts` | `AlertsScreen` | tab |

**Redirect logic** (`app_router.dart`, `routerProvider`):
- If the current month has no budget yet (`currentBudgetProvider.value == null`), every
  location redirects to `/onboarding`.
- Once a budget exists, visiting `/onboarding` redirects to `/dashboard`.
- Sign-in is **not a gate** — the app is fully offline-capable, so nothing forces a user
  through `/sign-in`. It stays reachable only from Settings.
- The redirect waits for `currentBudgetProvider` to resolve (`isLoading`/`hasError` → no
  redirect yet) so a cold start doesn't flash onboarding before bouncing back.

Insights and Settings are deliberately **not** part of the `ShellRoute` — they're registered
as top-level `GoRoute`s so they get a normal push transition and the system back button,
instead of living inside the persistent bottom-nav frame.

Navigation is **four tabs**, not five: Home (Dashboard) / Ledger / Goals / Alerts.

## Layering convention (per `CLAUDE.md`)

Every `features/<feature>/` folder follows the same subfolder contract:

| Folder | Holds | May import |
| --- | --- | --- |
| `domain/` | Immutable models, feature-specific rules | `budgetwise_domain` only |
| `data/` | API calls, repository impls | `domain/` |
| `application/` | Riverpod providers, orchestration | `domain/`, `data/` |
| `presentation/` | Screens, widgets (everything listed above) | `application/`, `domain/` |

A widget importing `data/` directly is a review rejection — it's what keeps the money math
testable without a network.
